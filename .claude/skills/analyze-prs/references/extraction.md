# PR 本文・外部目標からの情報抽出

PR の `body` や外部目標 Markdown から構造化情報を引き出すための検出パターンと、社内公開向けフィルタの詳細。

## PR body の検出パターン

### 残タスク・TODO

```
- 「## 残タスク」「## 🔜 残タスク」セクション
- 「- [ ]」形式のチェックリスト（未完了のもの）
- 「〜は別PRで対応」「〜は後で実装」などの表現
- 「TODO:」「FIXME:」を含む行
```

### PR 間の関連性

```
- 「#123」形式のPR/Issue参照
- 「〜の続き」「〜を前提に」「〜に依存」などの表現
- 「Related:」「Depends on:」「Blocks:」などのセクション
```

### 背景・目的

```
- 「## 概要」「## 背景」「## 目的」「## Why」セクション
- 「## 📝 概要」などの絵文字付きセクション
```

### コード内 TODO

重要なファイルのみ、SKILL.md Step 3 で既に取得済みの `files` の path 配列に対して `grep` で `TODO:` / `FIXME:` を検出する。再度 `gh pr view` を呼ばないこと。1 コールでまとめて grep する（per-file の shell fork を避けるため）：

```bash
grep -nE "TODO:|FIXME:" file1 file2 file3 2>/dev/null || true
```

## 外部目標の扱い

取得した目標 Markdown は **そのまま LLM の分析文脈に渡す**。構造化抽出はしない（自然な推論で対応する）。取得失敗（404、認証エラー）は警告ログを出すだけで処理は続行する。`externalGoals` フィールドは空でよい。目標が未設定の場合は「外部目標は未設定」と JSON に記録し、レポートではこの節をスキップする。

### 社内公開フィルタ（必須）

目標ファイルにある以下のセクションは **読んでもよいがレポートに転載しない**。あくまで紐づけ推論のための内部文脈として使う：

- 「💭 検討事項」「📝 次のステップ」など、未確定の作業メモ
- 「📚 参照資料・関連ファイル」内のプライベート参照（例: `[[tasks/private/...]]`）
- 期末記入欄（`(期末記入)` プレースホルダ）
- 評価ランク・自己評価のドラフト

レポートには **「目標タイトル」と「紐づいた PR」のマッピング**、および **目標の狙い（Why）の 1〜2 行サマリ** だけを載せる。原文の長文ブロック（「狙い（Why）」「Actions」「評価基準」の本文丸ごと）はコピーしない。

### Obsidian Wikilink の扱い

- 目標 Markdown 内に `[[2026H2チーム目標]]` のような Wikilink があっても、**自動では辿らない**。必要なら `GOALS_PATHS` に明示的に追加してもらう
- 個人目標 + チーム目標のように関係性が強いファイルは、最初から両方を `GOALS_PATHS` に並べて渡しておく

### 目標構造（推論の手がかり）

- 「目標 1（メイン）」「目標 2」「目標 3」のように番号付きで並んでいる場合、それを `linkedGoals[].title` の単位とする
- 「会社への影響」「狙い（Why）」「Actions」「評価基準」のような H2/H3 見出しは目標の **メタデータ** として推論時のみ参照
- 個人目標とチーム目標の両方を渡された場合、PR が個人目標の Actions とチーム目標の Actions の両方に該当することがある。重複は許容し、`scope: individual` と `scope: team` を別エントリで載せる
